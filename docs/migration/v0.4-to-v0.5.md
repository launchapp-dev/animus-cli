# Migration: v0.4 → v0.5

> **Status (2026-06-01):** This document reflects the current v0.5 runtime
> model in this repo. The workflow runner is no longer shipped as an in-tree
> Cargo binary or release-archive artifact; the daemon now expects an installed
> external `workflow_runner` plugin.

## What changed

The biggest operator-facing change between late v0.4 and current v0.5 builds is
the workflow runner handoff from an in-tree binary to an external plugin:

| Surface | v0.4.x | Current v0.5 |
|---|---|---|
| Workflow phase execution | `ao-workflow-runner` / `animus-workflow-runner` standalone binary | `launchapp-dev/animus-workflow-runner-default` plugin binary |
| Release archive contents | Included workflow-runner binary | Includes only `animus`, `agent-runner`, and `animus-oai-runner` |
| Cargo workspace | Included the legacy `workflow-runner-v2` crate | Uses `crates/animus-runtime-shared/`; `workflow-runner-v2` is gone |
| Daemon preflight | Could rely on bundled/local runner binaries | Requires an installed `workflow_runner` plugin |

The canonical curated install remains:

```bash
animus plugin install-defaults --include-subjects --include-transports
```

That installs the default workflow runner, queue, subject backends, providers,
and web plugins expected by current docs and daemon preflight.

## Upgrade checklist

1. Stop the daemon.

   ```bash
   animus daemon stop
   ```

2. Upgrade the core CLI binaries.

   ```bash
   curl -fsSL https://raw.githubusercontent.com/launchapp-dev/animus-cli/main/scripts/install.sh | sh
   ```

3. Install or refresh the default plugins, including the workflow runner.

   ```bash
   animus plugin install-defaults --include-subjects --include-transports
   ```

4. Verify preflight passes.

   ```bash
   animus daemon preflight
   ```

5. Restart the daemon.

   ```bash
   animus daemon start --auto-install
   ```

## Legacy fallback behavior

Current daemon code still contains a compatibility resolver for older
environments:

- Preferred resolution target: `animus-workflow-runner-default`
- Legacy fallback names: `animus-workflow-runner`, then `ao-workflow-runner`
- Dev override: `ANIMUS_WORKFLOW_RUNNER_BIN=/abs/path/to/custom-runner`

That fallback exists to keep mixed-version machines limping along during an
upgrade, not as the primary v0.5 operating model. If logs mention a legacy
runner name, the machine is not on the preferred plugin-backed path yet.

## Release-archive expectation

Do not expect a workflow-runner executable inside current release tarballs or
zip files. The release workflow packages only:

- `animus`
- `agent-runner`
- `animus-oai-runner`

Install the workflow runner separately via plugin install flows.

## Fresh-install recommendation

For a new machine, the shortest correct sequence is:

```bash
curl -fsSL https://raw.githubusercontent.com/launchapp-dev/animus-cli/main/scripts/install.sh | sh
animus plugin install-defaults --include-subjects --include-transports
animus doctor
animus daemon preflight
```
